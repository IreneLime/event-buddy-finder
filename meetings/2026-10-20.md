## Project Idea

**Event Buddy Finder** helps people discover local events and find others who may want to attend. It will provide a shared event calendar, event-specific group chats, and ways for individuals and groups to participate: individuals can join events, while groups can post them.

## Proposed Features

### Event Discovery

- Browse events by date in a calendar or by category.
- Search and filter events, including by date, category, price, and capacity.
- Show event locations as pins on a map.
- Display event ratings.
- Load event listings with pagination.

### Event Posting and Attendance

- Create and update events with a name, date and time, category, location, and description.
- Show newly posted events on the shared calendar in real time.
- Let individuals join events and groups post events.
- Consider a daily limit on how many events a person can post.
- Require event verification by a “verified admin” (the exact approval process needs clarification).
- Notify registered attendees when an event changes; consider an event-bot message for people who have expressed interest.

### Profiles and Accounts

- Register, sign in, and log out with email and password; authenticate through Firebase and send a confirmation email.
- After email confirmation, direct the user to complete their profile.
- Profile fields under consideration: name, profile picture, email verification status, age or age range, gender, event-category preferences, hobbies, and program of study.
- Show a user’s event history, including events they posted and events they attend or registered for.
- Clarify whether users register as individuals, groups, or both, and which profile fields are required.

### Chat and Messaging

- Provide a group chat on each event page, with a button to open the chat.
- Only registered, email-authenticated users can join and send messages.
- Keep chat history for groups the user has joined.
- Consider direct messaging between users who share an interest in an event.

## Initial User Flow

1. A user registers through Firebase Authentication.
2. The app sends an email confirmation link.
3. After confirmation, the user completes their profile.
4. The user browses events, joins an event or posts one as a group, and can open the event’s group chat if authenticated.

## Open Questions to Resolve

- What does “verified admin” mean, and who approves an event?
- Should daily event-post limits be part of the first version?
- Are age, gender, and program of study necessary profile fields, or should some be optional?
- Will users be able to send direct messages, or will communication stay within event chats?
- Which discovery features (map, ratings, and advanced filters) fit the team’s timeline?
